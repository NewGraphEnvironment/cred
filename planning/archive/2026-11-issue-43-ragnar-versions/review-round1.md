## Findings

- **[severity: bug]** R/store.R:2626-2653 (`crd_store_update()`): an update that changes only the source record writes the store with the index never rebuilt. On a pre-0.4.0 store that leaves it upgraded, with only its L2 HNSW index usable. The index is rebuilt only in two cases: `if (length(to_ingest) > 0L)`, where ragnar's ingest rebuilds it, and `else if (length(dropped) > 0L)`, where `ragnar_store_build_index()` does. When neither holds but `same_rec()` is FALSE, the update still goes on to `.crd_sources_write()`, `.crd_ragnar_stamp_write()` and the rename. The working copy was opened with `ragnar_store_connect(work, read_only = FALSE)`, so ragnar 0.4.0 has already upgraded it and recreated its HNSW indexes without their metric. That copy then replaces the store. The common way to reach this is exactly the population this branch is about: a store built by cred <= 0.6.x has no `cred_sources` table, and it was built under ragnar 0.3.x. Its first `crd_store_update()` with no Zotero changes marks every document `unrecorded` and takes this path.
  - **Reproduced** in a detached worktree of HEAD (since removed) with `pkgload::load_all()` and the test file's own `local_update_world()` / `build()` / `update()` helpers. Steps: build keyA and keyB, apply `.crd_test_to_pre040()`, drop `cred_sources`, then `update(path, c("keyA", "keyB"))`. Before the update, `.crd_test_cosine_indexed(path)` is TRUE. The update reports `Recording the md5 of 2 stored file(s)...` then `Store updated: ... added: 0 | replaced: 0 | removed: 0`. Afterwards the md5 has changed, `.crd_test_schema()` gives `content_hash = TRUE, fk = 0, hnsw = 3`, and **`.crd_test_cosine_indexed(path)` is FALSE**. Cosine queries, ragnar's default metric, now scan the whole table until someone rebuilds the index by hand.
  - Four copies of the same claim are false on this path, so this is a sentence to grep, not a single fix: `?crd_store_update` ("The update rebuilds the index, so search works as on a fresh build"), NEWS.md ("`crd_store_update()` upgrades a store only when it changes it, and rebuilds the index"), `research/ragnar-versions.md` ("Every update that changes something rebuilds the index") and the new CLAUDE.md bullet ("`crd_store_update()` (which always rebuilds the index when it writes)"). The new pre-0.4.0 update tests all reach the ingest or drop branches, so none of them covers this path.
  - Suggested fix: once the update has decided to keep the copy, call `ragnar::ragnar_store_build_index(store)` if neither branch rebuilt the index (for example, track a `rebuilt` flag). Add a test in the shape of the probe above.
  - **Rule:** code-check.md "A fixture that cannot reach the failure mode" ; code-check.md "A fix lands in one of two callers that share a harness"
